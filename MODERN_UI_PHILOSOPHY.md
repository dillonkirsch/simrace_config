# A purposeful desktop workspace

Sim Controls Manager should make useful information easy to find and changes
easy to review. Compact does not mean tiny, and calm does not mean empty.

Use the full available width for simulator relationships, editors, and history.
Give each page the layout its task needs while keeping typography, surfaces,
controls, and interaction states consistent. Distinguish the shell, workspace,
sections, and interactive controls with neutral surface steps. Reserve blue for
intent, mint for verified status, amber for attention, and coral for errors or
destructive actions. Status must remain understandable without color.

Overview should explain the actual setup and pending work. Deck Studio should
focus on its canvas. Control Map should prioritize its data. Bindings should make
the source-to-target relationship explicit. Recovery should make saved changes
browsable and their integrity understandable. Never fill space with invented
data or hide a feature to simplify a layout.

Preserve standard Windows window behavior and the existing preview, backup,
conflict, process-guard, and restore checks. Smaller windows should scroll content
without hiding important actions. Verify empty and populated states by running
the native application. See [DESIGN.md](DESIGN.md) for the implemented tokens,
components, layouts, and visual QA procedure.
